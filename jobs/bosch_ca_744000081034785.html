[2WP] システム・フィーチャー・アーキテクト / System Feature Architect

Company: Bosch Canada Location: Yokohama, Kanagawa, Japan URL: https://jobs.smartrecruiters.com/BoschGroup/744000081034785--2wp-system-feature-architect

企業概要

Two-Wheeler & Powersports is part of the Bosch Mobility Solutions business sector, bundling Bosch’s two-wheeler and powersports activities cross divisionally. Combining the areas of vehicle motion & safety, environment & efficiency and comfort & fun in one business unit we act as the one face to the customer, facilitating internal and external processes. We are globally responsible for sales, marketing and engineering for two-wheeler and powersports specific products.

With our headquarter in Yokohama, Japan and branches in the United States, Europe, India, ASEAN and China, we coordinate two-wheeler and powersports activities all around the world.

求人内容

本ポジションは、システム全体の設計思想を形作り、機能/サブシステムのアーキテクチャを定義する中核的な役割を担います。特に、高度な専門性が求められる機能安全とセキュリティ領域において、その要件をシステムに落とし込み、安全で堅牢な製品開発を実現していただきます。

主な職務：

  • システムアーキテクトと協調し、機能/サブシステムのアーキテクチャに関する方向性、および目標を設定・定義します。
  • 既存システムアーキテクチャの課題を特定し、改善提案と実行を主導します。
  • プロジェクトの特性に応じた最適な開発プロセスを立案・調整し、継続的な改善を推進します。

具体的な業務：

  • システム機能の企画からリリースまで、エンド・ツー・エンドでの責任を持ちます。
  • サブシステム全体のコンテキストを理解し、外部インターフェースを含めた連携を設計します。
  • 関連するシステムアーキテクトと密接に連携し、機能/サブシステムのアーキテクチャ定義や目標設定を整合させ、ドキュメント化します。
  • 製品全体のユースケースに基づき、担当する機能/サブシステムの機能的ユースケースを詳細化します。
  • 機能/サブシステムの分解構造（機能アーキテクチャ）を設計し、内部インターフェースを明確に定義します。
  • 複数の代替アーキテクチャ案を評価・比較し、最適なソリューションを選定。その設計判断プロセスを明確に文書化します。
  • 機能/サブシステムの静的および動的な振る舞いを詳細に定義します。
  • 関連ドメイン（主にインターフェース関連）との密な連携・調整を行います。
  • FAM（故障モード解析）、FMEA（故障モード影響解析）などの重要な分析活動をサポートします。
  • 【機能安全】 機能安全担当者が定義した要件に基づき、それらを機能/サブシステムアーキテクチャに適切に組み込みます。
  • 【セキュリティ】 機能セキュリティ担当者が定義した要件に基づき、それらを機能/サブシステムアーキテクチャに適切に組み込みます。

Key Responsibility:

  • Define architecture drivers and goals for the function / sub-system with system architect
  • Be able to recognize not optimal system architecture and propose improvement
  • Be able to tailor processes to project need and provide process improvement proposals

Scope / Task Definition:

  • End-to-end responsibility for the System Feature
  • Understanding of Subsystem Context & external interfaces of the function / sub-system
  • Align and document architecture drivers and goals for the function / sub-system with system architect
  • Derive functional use-cases for the function / sub-system from product level use-cases
  • Create function / sub-system break-down structure (function architecture) - definition internal interfaces
  • Evaluate alternative function / sub-system architectures and select winning solution + document design decisions
  • Define static and dynamic behaviour of function / sub-system
  • Alignment with domains (mainly on interfaces)
  • Support other analysis, like FAM, FMEA, etc.
  • Functional Safety - Implement functional safety needs (defined by functional safety responsible) in function / sub-system architecture
  • Security - Implement security needs (defined by functional security responsible) in function / sub-system architecture

  • 技術的専門性： システムズエンジニアリングにおける豊富な経験、または関連アプリケーションにおける深い実務知識。モデルベースシステムズエンジニアリング（MBSE）およびシステムアーキテクティングに関する主導的実践レベルの経験。システム機能の開発および分解に関する主導的実践レベルのノウハウ。V&V（検証と妥当性確認）のためのシステム戦略に関する主導的実践レベルの経験。要件エンジニアリングに関する実践レベルの知識、または関連アプリケーションでの実務経験。機能ベースの機能安全およびシステムセキュリティに関する深い理解。 【ツールチェーン】 SysMLを用いたモデリング経験（Enterprise Architectまたはその他）。要件およびテスト管理ツール（CodeBeamer）の使用経験。
