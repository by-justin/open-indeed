Job Description:

Software Engineer II - Release & Deploy

About the role

We are looking for a hands-on engineer to improve how a digital banking platform is built, released, and operated. You will coordinate deployments, maintain and troubleshoot CI/CD workflows, support environment readiness, and use monitoring data to help resolve availability and performance issues.

This role works across application, infrastructure, operations, security, and enterprise platform teams. It is well suited to someone who can understand an existing delivery process, work methodically during a release or incident, and turn recurring manual work into reliable automation.

What you will do

Release and deployment management

•  Coordinate application and infrastructure releases across non-production and production environments.

•  Support release planning, readiness assessments, implementation activities, and post-deployment validation.

•  Create, review, and maintain CI/CD workflows, including reusable patterns shared across multiple repositories.

•  Troubleshoot failures across builds, tests, security scans, artifact publication, infrastructure changes, and application deployments.

•  Support release windows and maintenance events, including health verification and rollback when required.

Change management and governance

•  Create and maintain change records, implementation plans, validation steps, rollback procedures, and release evidence.

•  Ensure releases meet enterprise risk, audit, security, and change-management requirements.

•  Coordinate technical reviews and approvals with application, infrastructure, operations, and platform stakeholders.

•  Maintain repository and release controls such as required checks, code ownership, branch protection, release tags, and secure secrets handling.

Environment and release readiness

•  Assess environment readiness and manage deployment dependencies across development, test, and production environments.

•  Monitor environment health and deployment performance, identifying configuration drift, dependency failures, and other risks to delivery.

•  Use application performance monitoring, centralized logs, distributed traces, and correlation IDs to triage availability and performance issues.

•  Improve dashboards, service-level indicators, synthetic checks, and alert routing so operational issues are visible and actionable.

•  Support technical incident investigation and drive assigned follow-up actions to completion.

Technology currency and modernization

•  Support platform upgrades, pipeline version updates, cloud migrations, and other technology-currency initiatives.

•  Adapt delivery workflows for both application and infrastructure changes while aligning with shared enterprise pipeline standards.

•  Test workflow changes with a controlled set of services before wider rollout, using clear validation and rollback criteria.

•  Contribute to container and Kubernetes delivery practices, and support pipelines for independently released front-end modules as these capabilities evolve.

Documentation and continuous improvement

•  Develop and maintain release runbooks, deployment standards, operational procedures, and troubleshooting guides.

•  Automate repetitive release and support tasks to reduce manual effort and operational risk.

•  Use deployment, incident, and reliability metrics to identify and prioritize improvements.

•  Turn lessons from failed releases and production incidents into durable process or automation changes.

Stakeholder engagement

•  Collaborate with development, infrastructure, operations, security, and platform teams to deliver releases successfully.

•  Communicate release status, deployment risks, environment issues, and implementation results clearly to technical and non-technical stakeholders.

•  Escalate issues with concise evidence and coordinate ownership when resolution spans multiple teams.

Required technology experience

You should bring hands-on experience with CI/CD, Azure infrastructure, and production monitoring. Experience with comparable enterprise tools is also relevant.

•   CI/CD and source control: GitHub Actions, reusable workflows, event triggers, environments, approvals, secrets, hosted or self-hosted runners, Git and repository controls.

•   Cloud and infrastructure as code: Microsoft Azure and Terraform, including plan and apply workflows, modules, remote state, application hosting, configuration, diagnostics, and platform metrics.

•   Observability: Dynatrace for service health, dashboards, distributed tracing, alerting and synthetic monitoring, plus centralized logging with Splunk, Datadog or a comparable platform.

•   Automation and build support: Linux, Bash or Python, Docker, and enough Java/Maven and Node.js/npm knowledge to diagnose build and pipeline failures.

•   Release ecosystem: Working familiarity with enterprise change management, security scanning, artifact management, and secrets management using tools such as ServiceNow, SonarQube, Veracode, Sonatype Nexus and HashiCorp Vault, or comparable products.

The role does not require application feature development, but you should be comfortable reading build output, configuration, and service logs well enough to collaborate with Java and web development teams during delivery failures and incidents.

What you bring

•  Experience supporting releases and production operations for customer-facing systems.

•  Ability to understand and safely modify pipeline code and configuration you did not originally write.

•  Strong troubleshooting skills across application, pipeline, infrastructure, and external-dependency boundaries.

•  Sound judgment when balancing delivery speed, availability, security, and compliance.

•  Experience working within formal change controls and supporting implementation or maintenance windows.

•  Clear written and verbal communication, including runbooks, change plans, incident updates, and technical defect reports.

Additional experience that is useful

•  Jenkins-to-GitHub Actions migration or standardizing workflows across multiple repositories.

•  Kubernetes, Azure Kubernetes Service and Helm, including deployment troubleshooting, autoscaling, ingress and progressive delivery.

•  CI/CD for micro-frontends or independently released web modules, including dependency compatibility, asset versioning and rollback.

•  SQL Server and asynchronous messaging technologies such as JMS or Kafka.

•  Regulated financial services, audit evidence, or segregation-of-duties controls.

What success looks like

•  Releases are prepared and executed consistently, with clear validation, rollback, and change evidence.

•  Workflow updates are tested and adopted predictably, with fewer deployment failures and less configuration drift.

•  Availability issues are localized faster through useful telemetry, actionable alerts and current runbooks.

•  Repetitive operational work is automated, improving release reliability and reducing support effort.
