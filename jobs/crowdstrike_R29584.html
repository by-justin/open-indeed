About the Role We're looking for a Senior UI Platform Engineer to lead the design and build of the shared developer tooling foundation for our next-generation front end. It's a strategic role for someone who wants to shape how hundreds of UI engineers scaffold, build, integrate and ship their code across the organisation.

UI Platform owns the paved road for UI engineering at CrowdStrike. As Product Groups migrate onto the new UI, we're consolidating developer tooling, build infrastructure, dependency management and CI into a single internal platform that teams pick up themselves. This role is central to that mission and you'll build the module federation foundations, build pipelines, scaffolding and automation that every UI team relies on to stay productive at scale.

What you'll do

  • Own the module federation architecture that lets dozens of Product Groups ship independent microfrontends into a single UI shell, keeping contracts stable, versions honest and cross-team breakage rare.
  • Lead the shared Vite build and dev-server tooling that every UI engineer runs locally and in CI, keeping hot reload fast, sub-package watch reliable and cold starts honest.
  • Design and run the CI pipelines that build, verify and publish every UI package across GitLab CI and Jenkins, keeping them fast, cacheable and giving engineers a clear signal when something breaks.
  • Ship the single CLI that is the front door to the platform to scaffold a repo, wire it into module federation, run its tests, cut a release with one command for everything a UI engineer does locally and in CI.
  • Wire automated dependency management (Renovate), security scanning and AI-assisted upgrades into the paved road so version bumps, vulnerability response and monorepo hygiene don't fall on individual teams.
  • Shift left: move linting, type checks, build validation and contract checks into the developer's editor and pre-push hooks so engineers catch issues in seconds, not in a failed pipeline twenty minutes later.
  • Work with UI Quality, UI Release and Observability so the platform feels like one thing through a single CLI.
  • Pair with Product Group leads to migrate legacy build and tooling patterns onto the paved road and get the tooling strategy adopted across the organisation.
  • Mentor engineers on build tooling, module federation and monorepo patterns, and give thoughtful code review across the platform and its consumers.
  • Build the ephemeral environments and preview deployments per MR so engineers get fast, honest feedback on their changes before they merge.

What you'll need

  • You've built shared frameworks, tooling or platforms that other engineers rely on day to day.
  • You know Vite and modern front-end build tooling well, and you're comfortable diagnosing issues deep in the module graph.
  • You've shipped module federation (or equivalent microfrontend architecture) in production at scale, and you understand the versioning, contract and runtime pitfalls.
  • You're fluent in TypeScript, monorepo tooling (Nx, Turborepo or similar) and modern package management (pnpm workspaces).
  • You've designed GitLab CI pipelines that stay fast and reliable and give engineers a clear signal when something breaks.
  • You've automated dependency management (Renovate or similar) and pulled security tooling (SAST, SCA, Snyk) into developer workflows.
  • You've set engineering standards that autonomous teams have genuinely adopted, and you can influence senior engineers and leaders when it matters.
  • You've used AI in earnest to change how engineering work gets done, not as a novelty.
  • You don't need to tick every box. If most of the "What you'll need" list sounds like you, we'd like to hear from you.

Bonus points

  • Playwright and modern browser test tooling wired into CI as a fast, reliable signal.
  • Running Jenkins alongside modern CI during a platform migration.
  • Ephemeral preview environments per MR and the infrastructure automation behind them.
  • Developer experience metrics like DORA or SPACE, and using them to drive tooling investment.
  • Contract testing between federated remotes in a large distributed front end.
